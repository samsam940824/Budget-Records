# 自動記帳（通知版）

銀行 App、LINE Pay、錢包跳出付款通知時，iPhone 捷徑的「收到通知時」自動化把通知文字送到 Supabase Edge Function `notify`。它會解析金額與類型、避免重複，然後直接入帳、合併到既有記錄，或放進網頁右上角 🔔「待確認」。

```
銀行 App／LINE／錢包通知 ──▶ iPhone 自動化（收到通知時）──(Bearer token)──▶ notify ──▶ 記錄 或 待確認
```

## 避免重複的規則

- 銀行每筆交易只發一則通知，所以**同一個來源的兩則通知一定是兩筆消費**（連刷兩杯 65 元咖啡會記兩筆）。
- **不同來源描述同一筆消費會合成一筆**：LINE Pay＋刷卡通知、Apple Pay＋刷卡通知（10 分鐘內），或先手動記帳、30 分鐘內才收到通知。
- 同一則通知 90 秒內又送一次，會放進待確認並標「疑似重複送出」，不會直接丟掉。
- 判斷不出來的一律放進待確認，**不會自動刪除任何記錄**。
- 合併錯了：交易詳情最下面「來源」按「拆開」。故意重複的記錄：編輯時打開「這是另一筆」。
- CSV 匯入會略過已經在帳本裡的列（日期前後 3 天、金額和帳戶相同）。

## 一次性部署（自架者）

1. 在 Supabase SQL Editor 依序執行 [`0004_notification_inbox.sql`](../supabase/migrations/0004_notification_inbox.sql) 與 [`0005_needs_purpose.sql`](../supabase/migrations/0005_needs_purpose.sql)。退回用 [`supabase/rollback/`](../supabase/rollback/) 裡對應的檔案。
2. 部署 Edge Function，並**關閉 JWT 驗證**：
   ```bash
   npx supabase functions deploy notify --no-verify-jwt --project-ref <你的 project ref>
   ```
3. Token 與[快速記帳捷徑](QUICK_ENTRY.md)共用，不需要另外產生。

## 建立自動化

需要兩個自動化：銀行與錢包類 App 全部收；LINE 只收 LINE Pay，避免聊天訊息被送出。兩個自動化的動作完全相同。

開始前準備：
- **網址**：`https://<你的 project ref>.supabase.co/functions/v1/notify`（網頁「設定 → 自動記帳」也看得到）。
- **Token**：打開「記帳」捷徑，複製「取得 URL 內容」標頭裡 `Bearer ` 後面那串。也可以到網頁重新產生，但那樣要同時更新「記帳」捷徑。
- 各 App 要開推播；LINE 要開「設定 → 通知 → **顯示訊息預覽**」，否則通知裡沒有金額。

### 自動化 A：銀行與錢包

捷徑 App → 「自動化」分頁 → ＋ → **App 通知**（收到通知時）
- App：**玉山銀行、國泰世華 CUBE、錢包、全盈+Pay、icash Pay**（用 uTagGo 推播的話也加入）
- 名稱／副標題／訊息條件：**全部不設**
- 選「**立即執行**」，關閉「執行時通知」

動作：
1. **文字**：內容放入〔捷徑輸入〕
2. **取得 URL 內容**
   - URL：貼上網址
   - 方法 `POST`；標頭新增 `Authorization`，值為 `Bearer ` 加上 token（Bearer 後面有一個空格）
   - 要求本文選「JSON」，新增一個欄位：鍵 `text`，類型「文字」，值〔文字〕

測試期間可以再加兩個動作，看每則通知被怎麼處理，確認沒問題後刪掉：

3. **取得字典值**：從〔URL 的內容〕取得「**所有數值**」
4. **顯示通知**：內容〔辭典值〕

### 自動化 B：LINE Pay

同上，但：
- App 只選 **LINE**
- 條件加「**名稱** 包含 `LINE Pay`」
- 動作與自動化 A 相同

## 第一次收到通知之後

- 第一次出現的通知會放進 🔔 待確認（原因「需要選帳戶」）。選好帳戶並保持「**記住這個選擇**」，之後同類通知就會自動入帳。
- 玉山「提台幣」、國泰「帳戶出帳／入帳」不知道用途（繳卡費、領錢、轉帳），每次都會請你確認。
- 看不懂的格式（例如第一次的 LINE Pay、Apple Pay）會連同原文放進待確認，可以把原文提供給開發者加上解析規則。

## 已知限制

- 同一個 App 同一秒的兩則通知，iOS 可能只觸發一次（例如國泰帳戶間轉帳的出帳＋入帳）。漏掉的可以在網頁手動補記。
- 手機要真的收到並顯示通知；關閉推播或專注模式擋掉的通知不會觸發。
- 銀行改了通知格式時，那些通知會進待確認，需要更新解析規則。
- 通知原文在處理完 30 天後自動刪除，只保留解析結果。

## 常見問題

| 狀況 | 原因與處理 |
|---|---|
| 測試通知顯示「捷徑 token 無效」 | token 已被重新產生；更新自動化 A、B 與「記帳」捷徑的標頭 |
| 顯示「略過：不是消費通知」 | 正常：驗證碼、廣告、帳單提醒、聊天不會記帳也不會儲存 |
| 收到通知但什麼都沒發生 | 確認自動化是「立即執行」、App 有開推播；LINE 要開顯示訊息預覽 |
| 記錄重複了 | 打開其中一筆的交易詳情看「來源」；是誤判的話告訴開發者，並刪掉多的那筆 |
